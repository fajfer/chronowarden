# ADR-025: Alert lifecycle and webhook delivery

- **Status:** Accepted
- **Date:** 2026-10-12
- **Evidence:** maintainer decisions of 2026-10-12 (webhook alerting spec); issue #99
- **Supersedes:** none (extends ADR-022)

## Context

ADR-022 decided that Chronowarden sends Alertmanager-compatible webhooks to a secret's effective owner, with retries,
a delivery log and optional Standard Webhooks signing. It left open where alerts without an owner go, how often a
lasting condition is re-sent, and where signing secrets live.

## Decision

- Alerts are identified like Alertmanager's: a name plus labels, fingerprinted with SHA-256. **State alerts**
  (expiring soon, expired, rotation unconfirmed past the grace period, vault unreachable) fire when their condition
  starts, are **re-sent every `alerting.repeat_interval`** (default `1d`) while it lasts, and are sent once as
  **resolved** when it ends. **Event alerts** (rotated, rotation confirmed, period ended, snapshot created) fire once.
- Recipients: the webhook routes of the secret's effective owners. Alerts without an owner (vault health,
  compliance, unowned secrets) go to **`alerting.default_routes`** in config.
- Delivery is a persistent queue in SQLite worked by an in-process task: POST, 10 s timeout, no redirects, retries
  with backoff up to `alerting.max_attempts`; every attempt is logged. Deliveries are not audit events.
- A route's **signing secret is generated by Chronowarden** (`whsec_…`), shown once when signing is turned on, and
  stored in SQLite; the API never returns it again. Turning signing on or off is an audit event (without the
  secret).

## Consequences

- Alert state survives restarts, so a restart doesn't re-send everything; deleting the database does.
- The database now holds signing secrets: back it up and protect it like the config (README).
- Webhook timing follows the sync schedule (ADR-013): an expiry is noticed at the next sync after it happens.
- Until authentication (0.9) anyone who reaches the API can add routes and read the delivery log (ADR-022).
